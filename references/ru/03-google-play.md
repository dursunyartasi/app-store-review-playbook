# Сборка Android и Google Play

Play снисходительнее App Review, но блокирует релизы из-за бумажной части чаще, чем из-за кода — и на эти блокировки легко наткнуться.

## Разовая настройка

**Создание приложения в Play Console в первый раз делается вручную.** Пути через API нет.

Два необратимых выбора:
- **«Бесплатное» нельзя сделать платным после публикации.**
- Имя пакета постоянно, как bundle ID в iOS.

## Подпись и SHA-1, на котором спотыкаются все

Ты подписываешь **ключом загрузки**; Play переподписывает своим **ключом подписи приложения**, который генерируется только после первой загрузки AAB.

```bash
keytool -genkey -v -keystore ~/app-release-key.jks \
  -keyalg RSA -keysize 2048 -validity 10000 -alias app
```

Держи keystore вне репозитория. Дальше:

**Если используешь вход через Google, в Android OAuth-клиенте нужны ОБА отпечатка SHA-1** — твой ключ загрузки *и* ключ подписи приложения от Play (Play Console → Подпись приложений). Пропустишь второй — вход через Google сломается именно в сборке из Play, тогда как локальная сборка работает. Проверить на эмуляторе тоже нельзя: отладочный SHA-1 там не зарегистрирован. Функциональная проверка требует подписанной Play сборки на устройстве.

## Сборка

```bash
export ANDROID_HOME=/opt/homebrew/share/android-commandlinetools   # или твой путь к SDK
eas build --platform android --profile production --local --output ./app.aab
```

Без `ANDROID_HOME` Gradle сообщит «SDK location not found».

**Карты упадут без ключа.** `react-native-maps` на Android использует Google Maps и **падает при нативной инициализации**, если нет `app.json > android.config.googleMaps.apiKey`. iOS не затронут, потому что там по умолчанию Apple Maps — именно поэтому это уезжает в прод незамеченным. Проверь, что ключ попал: распакуй AAB и найди `com.google.android.geo.API_KEY` в манифесте.

## Загрузка

Перетаскивание работает, но остаётся ручным навсегда; типичный AAB больше 60 МБ, что выше любого лимита браузерной автоматизации. Автоматизируй через сервисный аккаунт Play и `eas.json > submit.android`.

### Ошибки публикации, которые ты увидишь

- **«Этот выпуск не будет доступен существующим пользователям, так как не позволяет им перейти на добавленные пакеты приложения».** → подними version code или, что лучше, публикуй сначала через внутреннее/закрытое тестирование.
- **«Этот выпуск не добавляет и не удаляет пакеты приложения».** → AAB загрузился неправильно. Проверь version code и загрузи заново.
- **Нативные символы отладки** должны быть в `native-debug-symbols.zip` с каталогами по ABI — `armeabi-v7a/`, `arm64-v8a/`, `x86_64/`, в каждом `libapp.so` — и **без записей `__MACOSX` и `.DS_Store`**.

## Декларации, блокирующие релиз

**Рекламный идентификатор.** Распакуй AAB и поищи `com.google.android.gms.permission.AD_ID`. Firebase Analytics требует разрешение и соответствующую декларацию «используется»; приложению без рекламы не нужно ни то, ни другое. **Правило: декларация должна точно совпадать с манифестом** — расхождение в любую сторону блокирует релиз, а собственный текст предупреждения Play может ввести в заблуждение относительно того, какая сторона неверна.

**URL политики конфиденциальности.** Должен возвращать 200. Нашу первую отправку в прод отклонили только потому, что заявленный URL отдавал 404; с приложением всё остальное было в порядке.

**Форма безопасности данных и анкета возрастного рейтинга.** Обе обязательны до прода. Отвечай по тому, что приложение реально делает; их сверяют с заявленными разрешениями.

**Страны распространения.** Проверь. Одно из наших приложений жило в проде, ограниченное **одной страной**, тогда как iOS раздавался на 175 — состояние, которое никто не выбирает намеренно.

## Чувствительные разрешения

Фоновая геолокация и `FOREGROUND_SERVICE_LOCATION` запускают декларацию разрешений Play, которая требует **демонстрационное видео** и проверку. Если они пока не нужны, заблокируй их явно, а не публикуй и застревай:

```json
"android": { "blockedPermissions": ["android.permission.ACCESS_BACKGROUND_LOCATION",
                                    "android.permission.FOREGROUND_SERVICE_LOCATION"] }
```

Добавишь позже осознанно, с готовыми декларацией и видео.

## Дедлайны target API level

Play перестаёт принимать обновления для приложений, пропустивших срок повышения target API level. Дата сдвигается каждый год. **Держи её на контроле** — узнать об этом в день релиза плохо.

## Про скорость Play

Play одобряет быстро, и это режет в обе стороны: сломанный релиз может оказаться в проде примерно за час, и **откатить его нельзя**. Наш вышел с падением на экране входа; единственным лекарством было выпустить исправленный version code и ждать. Сначала используй внутреннее тестирование. После публикации следи за числом сбоев в Play Vitals — именно так мы подтвердили, что фикс сработал (10 сбоев → 0).
